# Go SDK Contract

## Ownership and surface

This repository owns the `github.com/converge-ai-labs/a13n-sdk-go` module, generated bindings, semantic Agent workflow, tests and independent release lifecycle. Service owns authorization, execution, durable state and wire semantics. `contract/source.json` records exact pinned inputs; generating this SDK neither executes Service nor imports another SDK. A new pin does not publish a module or promise compatibility with arbitrary deployments.

The high-level workflow is **one finite Agent interaction**. `Client.Agent(id)`, `Thread(id)`, `Entry(threadID,id)` and `Run(id)` bind identities locally without I/O or authorization checks. `Agent.Start(ctx,text,...StartOptions)` and `Send(ctx,threadID,text,...SendOptions)` provide text-first submissions. `StartInput` and `SendInput` accept ordered public `Input.Content []Part`; TextPart, JSONPart, URLPart and AssetPart constructors own required discriminators. Duplicate parts and native JSON values are preserved. Explicit Input.Wire/InputFromWire conversions remain available for advanced callers. At most one options value is accepted.

Start/Send options retain every selectable NewThread/Message field without duplicating Agent ID or content. Public RunOptions, Configuration, Overrides and selected canonical nested aliases expose all supported workflow fields, including uncommon selections and native maps, without a competing schema hierarchy. Optional[T] aliases the canonical nullable type: zero value omits, Null sends explicit null and Value preserves its value, including empty containers. Pointer-valued fields distinguish nil from explicit false/zero/empty. Service owns validation and defaults; SDK adapters do not merge configuration or normalize content.

High-level keys are optional. An omitted IdempotencyKey chooses one random key once before dispatch and exposes it in the receipt or unknown-outcome error; an explicit key remains unchanged. A new omitted-key call is a new logical submission. No mutation is automatically replayed. Durable/cancellation-safe callers persist their own key and identical body before sending; generated keys are not promised recoverable when no call result or error reaches the application.

StartOptions.MessageHistory optionally imports completed native Pydantic AI model-message JSON on new Thread creation only. The canonical MessageHistory is []json.RawMessage; native request encoding preserves each message's nested object-key order and number tokens, which native provider adapters can render into model-visible strings. Maps are not a substitute for preserving an existing native export's order. Omission differs from explicit []. Service parses/bounds the native format (256 messages, 256 KiB normalized JSON); SDK does not create a competing message hierarchy or filter the seed. The immutable seed is submit-only, absent from Thread.Get, and participates in create idempotency. Send, resume and fork cannot re-import it; import is provenance, not proof of execution.

`Client.API()` exposes the complete generated low-level HTTP protocol on the same transport and lifetime, including public, workspace, organization and administrator operations. Its typed models, `WithResponse` status variants, CAS/idempotency headers, binary, persistent raw Thread SSE and the native Session stream are the advanced foundation, not a second handwritten route catalogue. `ParseJSON[T]` is an optional bounded decoding adapter for raw JSON responses; `Pages[T]` composes typed generated page calls lazily without changing generated wire semantics. There is no parallel full generated resource tree or hand-maintained route inventory. Generated `nullable.Nullable[T]` and union `As...`/`From...` helpers retain wire distinctions; local JSON Schema validation is not comprehensive. Models are keyed; Agents, Skills and other resources are identified by ID.

## Native Run configuration and model characteristics

`StartOptions.Options` and `SendOptions.Options` use public `RunOptions`, an alias of canonical `RunOptionsInput` also used by generated `Message.Options`. Its `Configuration` is `nullable.Nullable[RunConfigurationInput]`, distinct from `Overrides`. The SDK forwards omission, null and explicit object without merging or synthesizing fields. `RunConfigurationInput.AllowedHosts` retains omitted/null/array (including an explicit empty array), and `Extensions` retains omitted versus explicit empty maps and native nested JSON, including false, zero, empty strings/arrays/objects and null. Generated `RunOptionsOutput.Configuration` provides the accepted readback.

Service owns normalization, snapshot defaults, canonical idempotency, immutability conflicts and inheritance. A new Run's omitted/null configuration selects its default; steering against an active Run (`accepted` or `running`) retains its current value. An explicit object selects its entire snapshot. `next_run` can select a different one; a different explicit steer or pending-entry edit against an active Run (`accepted` or `running`) returns `run_configuration_immutable`. A sealed `waiting` Run is not active merely because it requires resume. Recovery, handoff, resume successors and child continuations retain the accepted snapshot. The SDK does not normalize hostnames or regexes, authorize URLs, classify DNS/TLS, enforce provider policy or implement extension namespaces. These semantics are owned by [the pinned Run contract](../contract/semantics/runs.md#run-configuration).

Generated Model characteristics preserve nullable `ImageInput` and native `ImageInputPolicy`, `VideoInputPolicy`, and `UrlInputSupportInput`/`Output` values separately from Model settings and Run configuration. Pointer-valued fields retain zero/false; null image policy differs from omission; an empty native-video URL subtype list differs from absence. Preparation, file/URL materialization, provider eligibility and encoded byte budgets remain Service/Harness responsibilities. Public Input constructors forward text, JSON, URL and Asset parts through StartInput, SendInput and atomic ResumeOptions.Input.

## Skill sync and Environment preparation

Canonical Agent Config and Overrides use one native `SkillSync` union with `SharedSkillSync` and `IsolatedSkillSync` variants. The generator factors their identical inline wire schema into a named Go union in its temporary input so nullable Overrides receive native JSON/As/From methods. Pinned snapshots remain unchanged. Public aliases expose the same types. An omitted or null override inherits the revision; an explicit policy replaces the whole block. The SDK does not expand defaults or merge modes. Service defaults to shared publication (`overwrite=true`, `cleanup=false`); isolated `cache_count=0` disables trimming. `Overrides.LazyEnvironment` preserves absent/null/false, including eager preparation. Standalone Environment reservation, backend creation, project-directory selection and supported sandbox providers stay Service-owned; SDK operations forward native configuration.

## Tool discovery, desktop waits and context usage

Canonical ToolSearch, ToolSearchConfig and ToolSearchGroup expose the schema-derived proxy discovery models. HTTP and Session JSON boundaries reject unknown fields, native mode, null config/groups and malformed groups. Omitted mode selects the Service proxy default. Run overrides replace the complete block; omission/null inherits the revision and groups:{} disables grouping. Discovery execution remains Service-owned.

Desktop control and assistance operations are generated on the shared transport. A desktop_control waiting Run completes the same finite exact-Run observer normally, retaining pending.desktop_control_id and full raw evidence. A desktop-only user pause may have empty calls/approvals; explicit Resume sends both empty maps and leaves readiness validation to Service. Mixed waits retain full-batch requirements. Agent-requested assistance requires the exact persisted assistance outcome plus every other pending answer. Completion is its own operation, not automatic successor creation. Control/Completion session_id is the caller's browser-session token, not a Service Session ID; epoch fences control. Local cancellation/close, viewer disconnect and lease expiry do not fabricate a durable answer. No SDK renew/reclaim/retry loop, implicit ordinary resume or successor-following is introduced.

ContextUsage is a native nullable read of the latest completed contribution, with exactly one selector validated by Service. ParseJSON[\*T] explicitly permits successful JSON null as nil and retains original raw/status/header evidence; non-pointer ParseJSON[T] still rejects null. Required nullable token/window values retain null rather than zero. The SDK computes no prompt estimate, aggregate, capacity or ratio. Session remains cursor-free, single-connection and without an extra default frame cap; an already-sealed fresh connection reports thread.last_run without replaying historical Items.

## Authentication, responses and ownership

An API key acts in its own Service-authorized workspace; the SDK does not discover or send a workspace selector for these calls. A session uses `WithSession(cookieJar, csrfCallback)` with no API key and `WithSessionWorkspace(id)` for semantic scoped methods. Session CSRF is supplied on writes. The generated low-level API **never** inherits that workspace setting: each scoped operation's params must set `XWorkspaceID` explicitly, while public/admin/deployment-wide operations remain unscoped. Explicit low-level scope is never silently overwritten. The CSRF callback must be safe under concurrent calls; `WithSession` rejects a nil callback.

The generated Model Provider surface includes status, authorize, callback completion, disconnect and account-specific model discovery, with explicit workspace params and native success/null/status models. Provider authorization is workspace-shared, not a personal Connection or principal credential. Service enforces `read` on status, `write` on authorization mutations, `run` on discovery, and the unconfined user-login prerequisite for hosted browser authorization. The SDK does not categorically reject API keys for manual authorization or create its own credential store/browser flow. `AuthorizationCallback` diagnostics redact the write-only callback URL while authorized JSON submission retains it. Hosted callback/client registration, PKCE, token exchange, refresh and revocation are server/operator boundaries; local serialization tests establish none of their external compatibility.

Every operation accepts a context. Client `Close` cancels locally owned work and closes idle connections, never remotely interrupts a Run. Submission mutations are not automatically retried (even with idempotency keys), because transport failure/cancellation does not prove rollback. Session authentication, credentials and write-only generated values never appear in SDK diagnostic strings; authorized wire serialization remains intact.

`Result[T]` retains typed Value, actual status and headers, including ETag and request ID. RawJSON returns an independent copy of original bytes for precision-sensitive decoding; generated WithResponse parsers remain unchanged. `ApiError` carries Service code/message/details, status, headers and request ID. Buffered `ParseJSON` has a configurable 16 MiB default bound and closes the response body; raw generated responses, generated `WithResponse` parsing and binary streams have their separate ownership/buffering contracts. `BinaryResult` owns its unbuffered body until the caller closes it. `Upload` sends multipart bytes without closing the caller's reader; `Asset.Download`/`DownloadTo` stream successful bytes. `TransportError` exposes safe stage/category and `ProtocolError` safe response category/status/request ID without raw bodies or sensitive transport causes. `ErrTransport`, `ErrProtocol`, `ErrClosed`, and context cancellation retain their identities. UnknownOutcomeError distinguishes attempted dispatch without a reliable submission/resume acknowledgement from known API rejection and local pre-dispatch failures. It retains the chosen key, safe operation, known identities, optional status/headers and native chained cause without logging arbitrary keys/IDs/bodies. Transport/cancellation, lost response bodies and malformed receipts may be unknown outcomes, including unacknowledged gateway HTTP failures. HTTP status alone or a code-only gateway JSON object does not establish rejection. A canonical Service error envelope requires string code/message, object details and a present string/null request_id; only that envelope establishes known API rejection. Locally unsendable header values are rejected before dispatch evidence is recorded. It confers no retry permission.

The generated params expose `IfMatch` on conditional routes, `IdempotencyKey` where Service requires one, and `XWorkspaceID` where session business scope applies. Service, not the SDK, decides precondition validity and stale writes. `nullable.Nullable[T]` distinguishes omitted, null and value on updates; null has field-specific meaning. `extra_body` and `extra_headers` on model settings preserve allowed map values and whole-object replacement semantics: Run over Agent over Model defaults; `{}` clears an inherited extra object. The generated `ModelConfigInput.Settings` / `ModelConfigOutput.Settings` pointers retain an omitted or explicitly empty native JSON map for other model backends, including nested JSON values. Upload references preserve full opaque IDs, including 32 hexadecimal digits; password writes preserve eight-character values and write-only redaction. The pinned schema owns those constraints; the SDK adds no password, upload-ID or provider-settings policy. The SDK does not duplicate provider policy or affinity inference.

`Pages(ctx, first, fetch, next)` yields one `Result[T]` at a time, including headers and actual status. Its caller supplies generated fetch and cursor extraction with captured stable filters. The iterator fetches only when advanced, stops on break/context cancellation, and rejects a repeated cursor. Bounded catalogues do not invent pagination. Run Items uses explicit ordinal windows, not this cursor iterator.

## Interaction and exact completion

Agent invocation returns \*Interaction directly. Receipt() is an identity record with Origin, ThreadID, optional EntryID/RunID, chosen IdempotencyKey and clearly labeled optional ProvisionalRunID. ReceiptEvidence optionally retains the original submitted Entry or resumed Run HTTP response; identity recovery fabricates neither. Thread(), Entry() and Run() accessors provide synchronized local handles; Entry is absent for resume/exact Run origins. Run is authoritative only after Entry consumption or explicit exact Run binding, never initial provisional assignment.

Observation is lazy: construction performs no reads, and the first Result or reader starts one owned observer. Entry.Observe constructs identity-based recovery with the same incorporation kernel; failed/withdrawn dispositions yield EntryDispositionError, not unrelated Run success. Consumed supplies the exact immutable assigned_run_id; the observer validates identities and reads that Run until sealed completed/waiting/failed/cancelled. Assignment may revert or eventually incorporate into another Run. It never follows Thread pointers or successors. Run.Observe constructs the same exact-bound Interaction; Run.Result delegates result-only observation to it. There is no authored Wait alias or second polling kernel.

RunOutcome exposes direct Status, full structured Output, optional Pending/Failure, ThreadID/RunID and exact Run. Text() returns string-only (string,bool), preserving empty string. Evidence() retains the original typed Run response and HTTP metadata. High-level Output is decoded from original response bytes with json.Number; DecodeOutput[T] likewise uses the original field without a float64 roundtrip. The common ParseJSON response owner also preserves exact numbers in typed RunView.Output and Submitted.Run.Output, including integers beyond float64 range, without changing generated WithResponse parsers. ParseJSON[generated.RunContent] likewise decodes saved JSON values with json.Number and retains original response bytes. Null, false, zero and empty containers remain values; Evidence preserves omission/null wire distinctions. Display Items are not its final reply source.

`Run.Items(ctx, ...RunItemsOptions)` reads one authoritative committed display window; at most one optional options value passes Before, After and Limit to the generated query unchanged. Service validates before >= 1, after >= 0, mutually exclusive bounds and limit 1–500 (default 200). Items have dense, 1-based Ordinal. A default read returns the newest limit and entire mutable tail even beyond limit; explicit bounds select an exclusive ordinal window. The response contains Run, Items and Complete, with no baseline, continuation, position or replay hint. Complete means sealed, not all history loaded. RunView has no DisplayPosition. No Items response establishes live coverage or repairs a provisional gap.

Run.Resume(ctx,Answers,...ResumeOptions) translates public Approve/Deny/Returned/Failed values into both canonical wire maps in one mutation, including explicit empty maps. Returned requires an explicit JSON value; nil means a null result. Deny reason preserves absent/null/empty. Service validates complete atomic coverage, permissions and exact waiting last Run. ResumeOptions.Input preserves absent/null/ordered content in that same successor creation, separate from answers. Resume returns the same finite Interaction bound to the distinct exact successor Run; it fabricates no Entry and exposes resumed HTTP provenance explicitly. It does not follow later successors or reset a supplied deadline after POST. Additional input is not an implicit answer or approval. `Run.Interrupt(ctx)` is the explicit remote mutation.

One observation deadline covers submission, Entry polling, Run polling, in-flight reads and SSE attachment/body. The invocation context wins; without a caller deadline the SDK supplies 300 seconds total, with a 500 ms polling interval. A shorter `Result` caller context cancels only that caller's wait, not the already owned interaction. Interaction Close cancels local observation/transport reads and joins its one owned observer, including when preview yield is paused. Closing an unstarted Interaction performs no read and reports local cancellation to Result. Closing/timeout do not approve queued work, replay mutation, follow another Run or interrupt remote execution.

A Thread's `LastRunId` names its most recently sealed Run of any outcome, whose nearest checkpoint seeds the next explicit message. Failed and cancelled Runs pause automatic advancement without erasing history or selecting an earlier successful Run. Normal `Agent.Send` continues completed, failed or cancelled history; `Resume` is only for an exact idle waiting last Run, not a general retry. The SDK does not resubmit, select an implicit fork or follow successors automatically.

## Finite frames

`Interaction.Next()` is a single-reader finite iterator over typed provisional stream frames. It does not attach SSE until the Entry is consumed and an exact Run is known. It excludes frames from other Runs and Thread-wide unscoped `changed` hints. Underlying parser variants are delta, boundary, changed, gap and reset; the finite Run-scoped interaction emits applicable delta/boundary/gap/reset. Its parser validates SSE framing, cursor, required fields, UTF-8 and bounded size. EOF inside an unfinished line, frame or UTF-8 code point uses bounded reconnection; complete malformed UTF-8/JSON remains fatal. Disabled or exhausted truncation recovery returns an ErrProtocol-compatible error. Only previously **applied** cursor IDs are sent as `Last-Event-ID`, and progress resets transient retry budget. The default finite reader adds no Run/position claim or display baseline. `GapFrame.Position` preserves a known canonical missing-range position or nil for unknown loss; it does not prove recovery. Closing observation does not acknowledge an unapplied frame.

One wait observer cancels SSE attachment/read when the exact Run seals, including when the HTTP response headers stall or no terminal SSE frame arrives. `Next()` returns `io.EOF` at natural finite completion or explicit local Close; transport/protocol/deadline/Entry errors are returned, not hidden. A terminal Run may have sealed before attachment, so the iterator can emit zero frames; retention and filtering prevent a promise of lossless history. Gaps/resets require authoritative Items readback. Raw Thread-wide persistent SSE is available through `Client.API()` with caller-owned body, not a second high-level stream product. Advanced readers supply the generated paired `Run`/`Position` query and optional `LastEventID` only from independently saved applied progress; missing, expired or incompatible hints are not evidence of missing uncovered output. The explicitly scoped reader advances only the same attempt's contiguous applied tail. A matching gap/reset, an uncovered sequence hole, or a newer attempt freezes both coverage and its hint. Later deltas or boundaries cannot heal that reader; the caller must obtain valid applied progress independently before explicitly reopening; an Items read supplies none. Prior coverage is retained as evidence, not changed to an invented empty baseline. The SDK does not fold displays, invent a baseline recovery facade, silently read back, or infer attempt/sequence from a Redis ID.

The delta wire has one raw `event` plus a required nullable `item`, never a typed operation alternative. `ItemRef` preserves required ID/kind/state and optional nullable `Ordinal`, `ResponseGroup`, arbitrary JSON-map `Failure` and canonical `MemorySources`, including omitted/null/value distinctions. Source kind/status and nonnegative file-byte counts follow the pinned stream schema; absent/null sources remain valid. `DeltaFrame.Event` retains the native AG-UI 1.0 JSON object, including camelCase IDs, `protocolVersion`, typed multipart tool/media content, child `subagentRunId`/parent attribution, native extension fields, metadata and required `CUSTOM.value: null`. The Service frame envelope's `RunID` is independent of payload `runId`; child lifecycle observations cannot complete the root finite interaction. Native child IDs may repeat parent IDs without being flattened. Run Items `Content` retains structured `result_parts` and attribution/omission/truncation data rather than coercing it to root text. The SDK validates transport framing, not AG-UI presentation state, and owns no reducer, history reconstruction or media processing. Authored input custom observations and generated assistant content remain distinct; presentation metadata is not access authority.

## Native Session observation

Client.SessionEvents(ctx, sessionID, SessionStreamOptions) opens one native Session stream on the shared Client transport, semantic workspace and lifetime. SessionStream has single-reader Next, concurrent idempotent Close and HTTP Response metadata retained after Close. It performs no automatic reconnect, remote cancellation or mutation retry. EOF ends one connection; caller-owned reopening starts a fresh server snapshot, without Last-Event-ID or progress query parameters. Persistent applications use Service's documented jitter/Retry-After reconnect policy.

SessionFrame is distinct from ThreadFrame and has no cursor. Thread/items/delta/gap/schedule/occurrence/app_ready variants embed canonical models generated exclusively from the pinned session-stream schema graph in generated/sessionstream. This graph owns native serialization names and continuation structures independently of HTTP input/output models; it is not a handwritten parallel wire hierarchy. The shared SSE parser enforces UTF-8 and complete framing. Known Session payloads are validated recursively against the bundled pinned JSON Schema before typed decoding; unknown event names are ignored before decoding and invalid known frames fail with ErrProtocol. MaxFrameBytes defaults to zero, imposing no SDK limit on native snapshots; a positive value selects a caller-owned frame bound. RawJSON preserves the complete original native payload.

Thread snapshots include current/last Runs and open entries. A current Run begins with items; an already-sealed last Run is represented in thread state without replaying items. Items replace the suffix from First and retain complete native normalization continuation, including recursive observer/fragment state, without an SDK reducer or assembler. Gap holds that Run's deltas until server-owned items repair; complete ends only that Run's display. AppReady follows committed Items, can repeat, and identifies readiness by (RunID, AppID) without a delta sequence or cursor. App open/resource/tool requests remain explicit native API calls. Session continuation is not an HTTP reconnect cursor or an Items readback field. The finite exact-Run Interaction remains the high-level Agent workflow.

## Saved content, Findings and provenance

The complete generated API includes Findings CRUD, finding-analysis list/start, finding-agent preparation, session message-author lookup and exact-Run content reads. They use the shared Client transport/authentication/lifetime and their native scope/CAS/idempotency params, without parallel authored resource wrappers. Provider model discovery returns ProviderModel with unchanged Slug/DisplayName and optional nullable characteristics; ChatGPTModel is retired.

Run Items can carry ContentRefs beside inline content. Service saves fields inline through 32 KiB, externalizes larger values through 16 MiB, and retains a truncated UTF-8 prefix above that bound (text/plain even for oversized JSON). Preview size is at most 4 KiB. Callers explicitly read RunContent by Run ID and reference ID; the SDK does not auto-expand, cache, concatenate or feed saved values into live preview. Committed reference reachability and Run read authorization govern content reads. Media type, null/structured/string values and truncation remain independent facts.

MessageAuthors may omit unavailable/foreign-session/non-message IDs; callers correlate by EntryId, never request-array position. Automatic memory sources appear in provisional END metadata and committed saved item content; END is not a checkpoint. MemoryRecordProvenance is optional nullable best-effort confirmed-write evidence; ContentMatches reports a digest comparison, not origin or causality. Current memory resource access has its own authorization.

## Optional text preview

Text() returns iter.Seq2[string,error] as a lazy projection of the same finite reader. It emits only root assistant string CONTENT with a trustworthy matching START, excluding explicit child/parent-subagent attribution and display:false. A bounded set supports at most eight active message IDs, including suppressed display:false START identities until END, with no transcript queue. Subsequent content of a suppressed identity stays excluded without repeated metadata. Child and excluded events do not imply holes in unrelated coordinate domains; envelope attempt/sequence continuity is tracked only for the exact Run's frames. An initial boundary establishes only its attempt/sequence coordinate, not active message state or repaired content. Later boundaries do not advance delta coverage: late/equal boundaries are valid without regression, while a boundary beyond received deltas interrupts the preview. Same-attempt duplicate or descending delta sequences interrupt instead of silently dropping frames. A visible END without a matching active START interrupts; an explicitly hidden unseen END stays excluded.

Gap/reset, missing/ambiguous starts, known sequence discontinuity, attempt change, unsupported string content, bound exhaustion, protocol parsing failures and exact-root CUSTOM a13n.stream.fragment framing cause typed sticky PreviewInterruptedError. Protocol interruptions retain their original cause through native error unwrapping. Canonical fragments carry opaque id/index/count/data for original CUSTOM JSON slices, not standard text suffixes. Attribution/hidden filtering precedes fragment handling. This is conservative unsupported framing, not a claim all fragments contain assistant text; there is no assembler, baseline repair, data substring inference or full display reducer. Unknown unframed CUSTOM events remain available raw and are ignored by preview.

Only one reader is active, including while preview yield pauses. One preview may begin; a stopped/interrupted preview is not restarted. Deliberate sequential Next after interruption remains valid; prior raw consumption interrupts a new preview's missing state. Interruption does not close the outcome observer, and Result remains available while the Interaction is open. Early break does not drain or close. Natural seal can yield zero chunks; preview never promises a lossless transcript or replaces Output.
