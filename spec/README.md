# Go SDK Contract

## Ownership and surface

This repository owns the `github.com/converge-ai-labs/a13n-sdk-go` module, generated bindings, semantic Agent workflow, tests and independent release lifecycle. Service owns authorization, execution, durable state and wire semantics. `contract/source.json` records exact pinned inputs; generating this SDK neither executes Service nor imports another SDK. A new pin does not publish a module or promise compatibility with arbitrary deployments.

The high-level workflow is **one finite Agent interaction**. `Client.Agent(id)` binds a local Agent ID, while `Client.Thread(id)`, `Client.Entry(threadID,id)` and `Client.Run(id)` identify Service resources; binding performs no I/O or authorization check. `Agent.Start(ctx, text, StartOptions)` / `StartPayload(ctx, MessagePayload, StartOptions)` create a Thread and submit initial input. `Agent.Send(ctx, threadID, text, SendOptions)` / `SendPayload` continue a specified Thread with this Agent; a Thread has no implicit Agent. The required `RequestKey` is caller-chosen. Start/Send options contain every user-selectable generated NewThread/Message field (without duplicating Agent ID or payload) and preserve nullable omission/null/value. `StartOptions.MessageHistory` is an optional pointer to the generated `MessageHistory` JSON-object slice: an omitted pointer differs from explicitly sending `[]`. Only Thread creation imports completed Pydantic AI model-message JSON, including user/model text and closed tool-call/result exchanges. Service parses and bounds the native format (256 messages, 256 KiB normalized JSON); the SDK neither creates a competing native message hierarchy nor locally rewrites/filters the seed. The seed is immutable, available on `Thread.Get`, and included in create idempotency replay; Send, resume and fork cannot re-import it. Unknown wire constraints remain Service-owned.

`Client.API()` exposes the complete generated low-level HTTP protocol on the same transport and lifetime, including public, workspace, organization and administrator operations. Its typed models, `WithResponse` status variants, CAS/idempotency headers, binary and persistent raw Thread SSE are the advanced foundation, not a second handwritten route catalogue. `ParseJSON[T]` is an optional bounded decoding adapter for raw JSON responses; `Pages[T]` composes typed generated page calls lazily without changing generated wire semantics. There is no parallel full generated resource tree or hand-maintained route inventory. Generated `nullable.Nullable[T]` and union `As...`/`From...` helpers retain wire distinctions; local JSON Schema validation is not comprehensive. Models are keyed; Agents, Skills and other resources are identified by ID.

## Native Run configuration and model characteristics

`StartOptions.Options`, `SendOptions.Options` and generated `Message.Options` share `RunOptionsInput`. Its `Configuration` is `nullable.Nullable[RunConfigurationInput]`, distinct from `Overrides`. The SDK forwards omission, null and explicit object without merging or synthesizing fields. `RunConfigurationInput.AllowedHosts` retains omitted/null/array (including an explicit empty array), and `Extensions` retains omitted versus explicit empty maps and native nested JSON, including false, zero, empty strings/arrays/objects and null. Generated `RunOptionsOutput.Configuration` provides the accepted readback.

Service owns normalization, snapshot defaults, canonical idempotency, immutability conflicts and inheritance. A new Run's omitted/null configuration selects its default; steering against an active Run (`accepted` or `running`) retains its current value. An explicit object selects its entire snapshot. `next_run` can select a different one; a different explicit steer or pending-entry edit against an active Run (`accepted` or `running`) returns `run_configuration_immutable`. A sealed `waiting` Run is not active merely because it requires resume. Recovery, handoff, resume successors and child continuations retain the accepted snapshot. The SDK does not normalize hostnames or regexes, authorize URLs, classify DNS/TLS, enforce provider policy or implement extension namespaces. These semantics are owned by [the pinned Run contract](../contract/semantics/runs.md#run-configuration).

Generated Model characteristics preserve nullable `ImageInput` and native `ImageInputPolicy`, `VideoInputPolicy`, and `UrlInputSupportInput`/`Output` values separately from Model settings and Run configuration. Pointer-valued fields retain zero/false; null image policy differs from omission; an empty native-video URL subtype list differs from absence. Preparation, file/URL materialization, provider eligibility and encoded byte budgets remain Service/Harness responsibilities. MessagePayload unions pass text, JSON, URL and Asset parts unchanged through StartPayload, SendPayload and atomic resume input.

## Authentication, responses and ownership

An API key acts in its own Service-authorized workspace; the SDK does not discover or send a workspace selector for these calls. A session uses `WithSession(cookieJar, csrfCallback)` with no API key and `WithSessionWorkspace(id)` for semantic scoped methods. Session CSRF is supplied on writes. The generated low-level API **never** inherits that workspace setting: each scoped operation's params must set `XWorkspaceID` explicitly, while public/admin/deployment-wide operations remain unscoped. Explicit low-level scope is never silently overwritten. The CSRF callback must be safe under concurrent calls; `WithSession` rejects a nil callback.

The generated Model Provider surface includes status, authorize, callback completion, disconnect and account-specific model discovery, with explicit workspace params and native success/null/status models. Provider authorization is workspace-shared, not a personal Connection or principal credential. Service enforces `read` on status, `write` on authorization mutations, `run` on discovery, and the unconfined user-login prerequisite for hosted browser authorization. The SDK does not categorically reject API keys for manual authorization or create its own credential store/browser flow. `AuthorizationCallback` diagnostics redact the write-only callback URL while authorized JSON submission retains it. Hosted callback/client registration, PKCE, token exchange, refresh and revocation are server/operator boundaries; local serialization tests establish none of their external compatibility.

Every operation accepts a context. Client `Close` cancels locally owned work and closes idle connections, never remotely interrupts a Run. Submission mutations are not automatically retried (even with idempotency keys), because transport failure/cancellation does not prove rollback. Session authentication, credentials and write-only generated values never appear in SDK diagnostic strings; authorized wire serialization remains intact.

`Result[T]` retains typed Value, actual status and headers, including ETag and request ID. `ApiError` carries Service code/message/details, status, headers and request ID. Buffered `ParseJSON` has a configurable 16 MiB default bound and closes the response body; raw generated responses, generated `WithResponse` parsing and binary streams have their separate ownership/buffering contracts. `BinaryResult` owns its unbuffered body until the caller closes it. `Upload` sends multipart bytes without closing the caller's reader; `Asset.Download`/`DownloadTo` stream successful bytes. `TransportError` exposes safe stage/category and `ProtocolError` safe response category/status/request ID without raw bodies or sensitive transport causes. `ErrTransport`, `ErrProtocol`, `ErrClosed`, and context cancellation retain their identities.

The generated params expose `IfMatch` on conditional routes, `IdempotencyKey` where Service requires one, and `XWorkspaceID` where session business scope applies. Service, not the SDK, decides precondition validity and stale writes. `nullable.Nullable[T]` distinguishes omitted, null and value on updates; null has field-specific meaning. `extra_body` and `extra_headers` on model settings preserve allowed map values and whole-object replacement semantics: Run over Agent over Model defaults; `{}` clears an inherited extra object. The generated `ModelConfigInput.Settings` / `ModelConfigOutput.Settings` pointers retain an omitted or explicitly empty native JSON map for other model backends, including nested JSON values. Upload references preserve full opaque IDs, including 32 hexadecimal digits; password writes preserve eight-character values and write-only redaction. The pinned schema owns those constraints; the SDK adds no password, upload-ID or provider-settings policy. The SDK does not duplicate provider policy or affinity inference.

`Pages(ctx, first, fetch, next)` yields one `Result[T]` at a time, including headers and actual status. Its caller supplies generated fetch and cursor extraction with captured stable filters. The iterator fetches only when advanced, stops on break/context cancellation, and rejects a repeated cursor. Bounded catalogues and Run Items do not invent pagination.

## Interaction and exact completion

Agent invocation returns `*Interaction` directly. It exposes the original `Receipt` with HTTP metadata, bound `Thread` and `Entry`, and optional receipt `Run` (nil for queued input). `Result(ctx)` does not require draining events. An owned observer waits for the Entry to become **consumed**, not merely assigned; queued input behind an approval may remain queued. Failed or withdrawn dispositions return `*EntryDispositionError` with safe summary and exact Entry snapshot, never unrelated Run success. A consumed Entry supplies the immutable `assigned_run_id`; the observer reads that **exact** Run until sealed at completed, waiting, failed or cancelled. It validates Entry/Thread/Run identity and never follows Thread latest pointers or a successor. Waiting/failed/cancelled are observable outcomes, not successful completion. A Run may be assigned, revert to pending and eventually be consumed by a different Run.

`RunOutcome` projects one authoritative `Result[generated.RunView]` (`Snapshot`) bound to its exact `Run`; `Status()`, `Output()`, `Pending()` and `Failure()` accessors read that snapshot. Output remains structured. `Run.Wait(ctx)` likewise observes exactly its bound Run; `Run.Items(ctx)` provides authoritative committed display, including its nullable `Position`, optional nullable `ResumeAfter`, `Complete`, `Dropped` and bounded item metadata. The display position establishes coverage; the Redis hint only optimizes retained replay. `Run.Resume(ctx, request generated.Resume, key)` submits the Service's complete `Approvals` and `Calls` maps keyed by exact pending call IDs and returns the distinct successor Run and response. The optional `Input` is a `nullable.Nullable[generated.MessagePayload]` attached to that same atomic successor creation, separate from any call result; it does not authorize work, resolve a question, or fill missing results. A waiting head must be resumed explicitly, including question-only waits; an ordinary Send stays queued and cannot close the wait. No omissions or partial answers receive defaults. Approval/call coverage, Pydantic AI questions, media, size and authority are validated by Service, not reimplemented by the SDK. `Run.Interrupt(ctx)` is the explicit remote mutation.

One observation deadline covers submission, Entry polling, Run polling, in-flight reads and SSE attachment/body. The invocation context wins; without a caller deadline the SDK supplies 300 seconds total, with a 500 ms polling interval. A shorter `Result` caller context cancels only that caller's wait, not the already owned interaction. Interaction `Close` cancels local observation and joins its one owned wait observer. Closing/timeout do not approve queued work, replay mutation, follow another Run or interrupt remote execution.

## Finite frames

`Interaction.Next()` is a single-reader finite iterator over typed provisional stream frames. It does not attach SSE until the Entry is consumed and an exact Run is known. It excludes frames from other Runs and Thread-wide unscoped `changed` hints. Underlying parser variants are delta, boundary, changed, gap and reset; the finite Run-scoped interaction emits applicable delta/boundary/gap/reset. Its parser validates SSE framing, cursor, required fields, UTF-8 and bounded size. Reconnection is bounded; only previously **applied** cursor IDs are sent as `Last-Event-ID`, and progress resets transient retry budget. The default finite reader adds no Run/position claim or display baseline. `GapFrame.Position` preserves a known canonical missing-range position or nil for unknown loss; it does not prove recovery. Closing observation does not acknowledge an unapplied frame.

One wait observer cancels SSE attachment/read when the exact Run seals, including when the HTTP response headers stall or no terminal SSE frame arrives. `Next()` returns `io.EOF` at natural finite completion or explicit local Close; transport/protocol/deadline/Entry errors are returned, not hidden. A terminal Run may have sealed before attachment, so the iterator can emit zero frames; retention and filtering prevent a promise of lossless history. Gaps/resets require authoritative Items readback. Raw Thread-wide persistent SSE is available through `Client.API()` with caller-owned body, not a second high-level stream product. Advanced readers supply the generated paired `Run`/`Position` query and optional `LastEventID` from an applied display snapshot; missing, expired or incompatible hints are not evidence of missing uncovered output. The explicitly scoped reader advances only the same attempt's contiguous applied tail. A matching gap/reset, an uncovered sequence hole, or a newer attempt freezes both coverage and its hint. Later deltas or boundaries cannot heal that reader; the caller must apply an authoritative snapshot and explicitly reopen with its position and optional hint. Prior coverage is retained as evidence, not changed to an invented empty baseline. The SDK does not fold displays, invent a baseline recovery facade, silently read back, or infer attempt/sequence from a Redis ID.

`DeltaFrame.Event` retains the native AG-UI 1.0 JSON object, including camelCase IDs, `protocolVersion`, typed multipart tool/media content, child `subagentRunId`/parent attribution, native extension fields, metadata and required `CUSTOM.value: null`. The Service frame envelope's `RunID` is independent of payload `runId`; child lifecycle observations cannot complete the root finite interaction. Native child IDs may repeat parent IDs without being flattened. Run Items `Content` retains structured `result_parts` and attribution/omission/truncation data rather than coercing it to root text. The SDK validates transport framing, not AG-UI presentation state, and owns no reducer, history reconstruction or media processing. Authored input custom observations and generated assistant content remain distinct; presentation metadata is not access authority.

## Verifiable invariants

- Generated verb/path/operation identity matches the exact pinned OpenAPI operation set, not only its count.
- Start/Send option fields and types cover every user-selectable generated input field, including imported history only on Start; generated low-level types preserve omitted/null/empty-value distinctions.
- Tests verify imported Pydantic AI JSON reaches both semantic and generated Thread creation unchanged, appears on Thread readback, and is absent from later Send; `Resume.Input` and the two complete result maps share one POST and raw replay retains its response metadata.
- Actual request JSON regressions cover Configuration omission/null/object, AllowedHosts null/empty, complete snapshot extensions with false/empty/nested values, independent Overrides, native media payloads and Service-owned immutability conflicts. Input/output Model image/video policies retain zero/false/empty values.
- Five OAuth/discovery operations have scoped key/session loopback wire tests, success/null metadata and callback diagnostic redaction. The schema-derived operation identity/method/path set covers the full pinned surface.
- AG-UI 1.0 media, ordered duplicate parts, null custom values, child/parent attribution and committed content are lossless JSON. A child terminal event cannot seal the root Interaction; exact authoritative Run completion and cancellation/Close ownership remain covered.
- Tests cover queued→consumed, assigned→pending→consumed by another Run, failed/withdrawn, waiting, exact Run, deadline/cancellation inside reads, no duplicate POST, and response identity mismatches.
- Finite tests cover immediate completion, idle SSE termination, blocked header attachment, filtering another Run, result-only use, early Close and race-enabled cancellation; parser tests cover malformed frames/reconnect/gap handling, nullable known/unknown gap positions, Run/position wire claims with missing/null/expired hints, no advancement across sequence holes and boundaries, gap/reset/attempt-change freezing until explicit snapshot reopen, and no implicit Run/position claims on the default finite path.
- Binary ownership, structured errors, response metadata, session scope, CAS and lazy pagination have focused tests and an isolated installed-module consumer. Local tests do not establish live provider compatibility or publication.
